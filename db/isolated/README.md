# قاعدة المعاينة المنعزلة

هذه مساحة **لتصميم PostgreSQL جديد وفارغ واختباره**. لم تُربط بمزود بعد، ولا تقرأ أو تنسخ أي بيانات من قاعدة قديمة.

## حدود صارمة

- لا نسخ أو استعادة أو استيراد من قاعدة البيانات القديمة، ولا ترحيل سجلات قديمة.
- لا تشغّل ملفات `supabase/migrations/` في جذر المشروع على القاعدة الجديدة؛ هذه سلسلة تاريخية منفصلة وبعض أرقامها متعارضة.
- لا أسرار أو عناوين اتصال في Git؛ لاحقًا تكون متغيرات الاختبار في Vercel Preview فقط، ولا تعديل على Production ضمن هذا العمل.
- لم يُنفّذ SQL على PostgreSQL حقيقي. الاختبارات الحالية لمحاكاة API محلية وفحوص ساكنة؛ لا تُعد دليلًا على صحة التنفيذ أو RLS في مزود فعلي.

## التسلسل على قاعدة جديدة فقط

1. `0001_clean_baseline.sql`: محتوى الموقع وإعداداته وسجلات الدول وجداولها التابعة.
2. `0002_admin_content.sql`: محتوى لوحة الإدارة، الباقات العامة، FAQ العامة، ووظيفتا الاستبدال الذري.
3. `0003_admin_editors.sql`: صفحات CMS، الودجات، theme، إعدادات هبوط السعودية والإمارات، المكتبة، فيديوهات الصف، المدونة، الصفحات القانونية، ملفات مستخدمي CMS وصلاحياتهم، وكتالوج الألعاب.
4. `seed.mock.sql`: بيانات اختبار اصطناعية فقط؛ لا تشغّلها على Production.

لا يحتوي التسلسل النظيف على طلبات أو مدفوعات. جداول `cms_users` ملفات تعريف وصلاحيات فقط، وليست نظام تسجيل دخول؛ يظل الدخول عبر جلسة الإدارة الحالية حتى تنفيذ تكامل هوية مستقل ومراجعته.

## سياسة الوصول والبيانات

- كل جداول `0003` مفعّل عليها RLS بلا سياسات للمتصفح. تستخدمها APIs الخادمية الموثقة عبر اتصال خدمة/مالك موثوق؛ لا تضع مفتاح خدمة في المتصفح.
- إعدادات السعودية والإمارات تُخزن كبيانات تحريرية. الأسعار الفعلية يجب أن تبقى مرتبطة بسجل البلد وعملته في `area_packages`، ولا تُقبل من JSON حر بوصفها مصدرًا بديلًا عن سجل البلد.
- الوصلات الخارجية للمكتبة والفيديوهات تُعرض كروابط/تضمينات؛ لا يعني ذلك إنشاء تخزين ملفات في قاعدة البيانات.
- قراءة لوحة الإدارة لا تُدرج بيانات افتراضية تلقائيًا. قد يعرض الموقع fallback محليًا عند غياب صف، لكن يجب ألا تعرض الواجهة رسالة حفظ ناجح ما لم ينجح API.

## إعداد الاتصال لاحقًا (Vercel Preview فقط)

بعد إنشاء قاعدة اختبار فارغة وتطبيق ملفات `0001` ثم `0002` ثم `0003` عليها، تُضاف القيم من إعدادات Vercel إلى بيئة **Preview** الخاصة بالفرع فقط:

- `NEXT_PUBLIC_SUPABASE_URL`: عنوان مشروع Supabase الجديد. هذا العنوان عام وليس كلمة مرور.
- `SUPABASE_SERVICE_ROLE_KEY`: مفتاح الخدمة الخادمي؛ لا تضف بادئة `NEXT_PUBLIC_` ولا تضعه في ملفات Git أو المتصفح.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD_SCRYPT_HASH`, `ADMIN_SESSION_SECRET`: بيانات جلسة إدارة هذا الفرع، تُولَّد وتُحفظ في Vercel فقط.
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`: يلزم فقط للأجزاء الأخرى التي تستخدم Supabase Auth/العميل العام؛ لا يمنح صلاحيات إدارة.

لا تُضبط Environment Variables على Production ضمن هذا العمل، ولا يُرسل أي مفتاح أو كلمة مرور في المحادثة. قبل إعلان الاتصال الفعلي، يختبر CRUD للإدارة، قراءة صفحات الموقع، وسلوك الصلاحيات/الـRLS على قاعدة الاختبار الجديدة. لا تُشغّل `seed.mock.sql` خارج قاعدة اختبار فارغة.

## دليل الاختبار الحالي

- اختبارات البيانات والمسارات تتحقق من منطق التطبيق.
- `tests/isolated-country-admin-preview.test.mjs` يشغل PostgREST وهميًا داخل الذاكرة وعلى loopback؛ ليس PostgreSQL ولا اختبارًا لمزود خارجي.
- قبل إعلان الربط جاهزًا فعليًا، طبّق `0001` ثم `0002` ثم `0003` على قاعدة اختبار فارغة، وشغّل قيود الجداول/RLS وCRUD لكل مجال. لا تستخدم بيانات الإنتاج.
