# خطة إصلاح SEO للصفحة الرئيسية وربطها بالكود وقاعدة البيانات

## الهدف

رفع قابلية قراءة الموقع لمحركات البحث، خصوصًا الصفحة الرئيسية وصفحات الدول، مع الحفاظ على إدارة المحتوى من لوحة التحكم وSupabase. الأولوية ليست إضافة كلمات كثيرة عشوائيًا، بل ضمان أن العنوان والمحتوى التجاري الأساسي يظهران في HTML الأولي قبل اعتماد الصفحة على JavaScript أو انتظار طلب قاعدة البيانات.

النطاق الحالي للموقع هو تعليم القرآن الكريم والتجويد وتأسيس اللغة العربية أونلاين، بحصص فردية باللغة العربية. لذلك يجب أن تبقى الرسالة واضحة: الموقع يخدم الناطقين بالعربية، مع استهداف أسواق محددة على مراحل بدل إنشاء صفحات دولية متشابهة بلا قيمة محلية حقيقية.

---

## 1. تشخيص مشكلة «جاري تحميل الصفحة»

### السبب المباشر في الكود

المسار الحالي في `app/page.tsx` يمر بهذه السلسلة:

```text
GET /
  └─ app/page.tsx
      └─ DynamicHeroContent()
          └─ await getPublicContent(homeContentKeys)
              └─ unstable_cache(...)
                  └─ siteContentRepository.getActiveByKeys(...)
                      └─ Supabase: site_content
      └─ Suspense fallback
      └─ HeroSection (client component)
```

المفاتيح المقروءة للـHero هي:

- `hero_title`
- `hero_subtitle`
- `about_badge`
- `about_title`
- `about_description`
- `mission_title`
- `mission_description`
- `vision_title`
- `vision_description`
- `goals_title`
- `goals_description`

لكن الـHero نفسه لا يحتاج كل هذه المفاتيح. جعل قراءة كل المحتوى داخل `DynamicHeroContent` يربط ظهور الـHero بزمن قراءة مجموعة كاملة من قاعدة البيانات.

### عامل إضافي

`app/loading.tsx` يعرض النص:

```text
جاري تحميل الصفحة...
```

وهذا النص يظهر أثناء انتظار رندر المسار أو أثناء التنقل. وجوده ليس مشكلة SEO بحد ذاته لو تم استبداله سريعًا بمحتوى الصفحة في HTML النهائي، لكنه يصبح مشكلة عندما يقرأ crawler أو أداة فحص الاستجابة المبكرة هذا الـfallback بدل المحتوى الأساسي.

### عامل ثالث

`HeroSection` معلن كـ`use client` لأنه يستخدم `useI18n`، مع أن المحتوى العربي الافتراضي معروف على الخادم. هذا لا يمنع Next.js من محاولة SSR للمكوّن، لكنه يزيد اعتماد الصفحة على شجرة Client Components ومزود اللغة. اللغة تبدأ دائمًا بـ`ar` من خلال `I18nProvider`، لذلك يمكن جعل النسخة العربية الأولى خادمية فعلًا، ثم إضافة التفاعل وتبديل اللغة بعد التحميل.

### عامل رابع

`getPublicContent` يعتمد على `siteContentRepository` الذي لا يُنشأ إلا إذا كان `supabaseAdmin` متاحًا. عند غياب الإعداد أو حدوث خطأ، يعيد `{}` وتعمل fallback strings داخل `HeroSection`. هذا جيد كشبكة أمان، لكن الشبكة لا تلغي وقت الانتظار قبل الوصول إلى `HeroSection` لأن الـ`await` موجود قبل الرندر.

### ملاحظة مهمة

المحتوى الثابت داخل `HomeContentSections` موجود داخل مكوّن Client، لكنه لا ينتظر Supabase. لذلك المشكلة الأكبر في الصفحة الأولى هي جعل الـHero وما قبله خلف قراءة CMS و`Suspense`، وليست كل الصفحة.

## 2. الإصلاح التقني المقترح لمشكلة التحميل

### الإصلاح المفضل: لا تجعل الـHero معتمدًا على قاعدة البيانات

ينبغي أن يظهر العنوان والوصف والـCTA الأساسي في HTML الأولي من قيم ثابتة موثوقة، ثم تستخدم قاعدة البيانات لتحديث المحتوى غير الحرج أو لإدارة النسخة التالية.

التعديل المقترح في `app/page.tsx`:

1. إزالة `homeContentKeys` من القراءة الأولى للـHero.
2. إزالة `DynamicHeroContent` من مسار الـHero.
3. تمرير نسخة عربية خادمية ثابتة إلى `HeroSection`.
4. إبقاء CMS للمحتوى الثانوي فقط، أو قراءته في قسم لاحق لا يحجب الـHero.
5. عدم وضع `HeroSection` داخل `Suspense` يحتاج إلى بيانات قاعدة البيانات.

شكل منطقي مقترح:

```tsx
const homepageHero = {
  title: "تحفيظ القرآن وتأسيس اللغة العربية أونلاين للناطقين بالعربية",
  subtitle:
    "حصص فردية مباشرة للأطفال والكبار والمبتدئين، للحفظ والمراجعة والتجويد وتأسيس القراءة والكتابة العربية.",
}

export default function HomePage() {
  return (
    <>
      <AcademyBanner />
      <HeroSection content={homepageHero} />
      <HomeContentSections />
      {/* المحتوى الاختياري أو القادم من CMS يأتي بعد المحتوى الأساسي */}
      <DeferredLandingVideoStrip />
      <Suspense fallback={<div className="min-h-72 bg-muted" aria-hidden="true" />}>
        <CTASection />
      </Suspense>
    </>
  )
}
```

هذا المثال يحتاج مواءمة الأنواع الحالية؛ الفكرة الأساسية هي أن العنوان والوصف لا ينتظران Supabase.

### بديل إذا كان يجب أن يبقى الـCMS مصدرًا للـHero

إذا كان مطلوبًا أن يعدّل المدير الـHero من لوحة التحكم، يتم التالي:

- قراءة `hero_title` و`hero_subtitle` فقط، وليس كل مفاتيح الصفحة.
- وضع timeout قصير لقراءة CMS، مثل 300–500ms، ثم استخدام fallback ثابت عند التأخر.
- عدم عرض `Suspense fallback` فارغ أو عبارة تحميل مكان الـHero.
- تمرير fallback إلى `HeroSection` فورًا عند فشل أو تأخر CMS.
- إضافة cache مستقل للـHero، مع invalidation عند حفظ مفاتيح الـHero.
- عدم استخدام قيمة قاعدة البيانات في `metadata` إلا إذا كانت القراءة مضمونة قبل إنشاء Metadata.

Pseudo-code:

```ts
const HERO_FALLBACK = {
  hero_title: { key: "hero_title", content_ar: "...", content_en: "...", content_fr: "..." },
  hero_subtitle: { key: "hero_subtitle", content_ar: "...", content_en: "...", content_fr: "..." },
}

async function getHeroContentWithFallback() {
  try {
    const result = await withTimeout(
      getPublicContent(["hero_title", "hero_subtitle"]),
      400,
    )
    return { ...HERO_FALLBACK, ...result }
  } catch {
    return HERO_FALLBACK
  }
}
```

لا ينبغي استخدام fallback مؤقت يحمل نصًا مثل «جاري تحميل الصفحة» في مكان الـH1.

### تعديل `app/loading.tsx`

`app/loading.tsx` يجب أن يبقى واجهة انتقالية عامة، لكن يُفضّل:

- إزالة النص الطويل «جاري تحميل الصفحة...» من واجهة الانتقال العامة أو جعله غير أساسي بصريًا.
- عدم وضع `h1` أو كلمات SEO في شاشة التحميل.
- استخدام skeleton محايد و`aria-hidden="true"` قدر الإمكان.
- اعتبار هذا الملف fallback للتنقل فقط، لا مصدر محتوى الصفحة.

صيغة أكثر أمانًا:

```tsx
export default function Loading() {
  return (
    <div aria-hidden="true" className="min-h-screen bg-background">
      <div className="h-20 animate-pulse bg-muted" />
      <div className="min-h-[70vh] animate-pulse bg-muted/40" />
    </div>
  )
}
```

لا يُفترض أن تعتمد محركات البحث على هذه الشاشة؛ المحتوى الحقيقي يجب أن يأتي من استجابة الصفحة نفسها.

### مراجعة `app/client.tsx`

يوجد ملف `app/client.tsx` يحتوي نسخة أخرى من تركيب الصفحة الرئيسية، بينما `app/page.tsx` هو المسار المستخدم فعليًا حسب الفحص. يجب التأكد هل `app/client.tsx` مستخدم في أي import. إذا لم يكن مستخدمًا:

- إما حذفه في تغيير منفصل بعد التأكد.
- أو تسميته بوضوح كنسخة legacy وعدم ترك منطقين مختلفين للصفحة الرئيسية.

وجود نسختين يزيد احتمال إصلاح نسخة وترك النسخة المنشورة تعتمد على المسار القديم.

## 3. التعديلات المحددة على العنوان والمحتوى الأول

### العنوان الحالي

العنوان الحالي في `app/layout.tsx`:

```text
أكاديمية الحافظ المتميز أون لاين | تحفيظ قرآن وتأسيس عربي
```

والعنوان الخاص بالصفحة الرئيسية في `app/page.tsx`:

```text
تحفيظ القرآن وتأسيس العربية أونلاين | الحافظ المتميز
```

العنوان الحالي جيد من حيث الموضوع، لكنه لا يوضح بسرعة كافية أن الخدمة فردية، باللغة العربية، وللأطفال والكبار. يجب عدم حشو العنوان بكل الدول أو كل المرادفات.

### العنوان المقترح للصفحة الرئيسية

```text
تحفيظ القرآن وتأسيس العربية أونلاين | الحافظ المتميز
```

يُحافظ عليه إذا كان طول العنوان النهائي مناسبًا، مع جعل قيمة `metadata.title` هي المصدر الوحيد للصفحة الرئيسية. لا نكرر عنوانًا مختلفًا من CMS دون سبب.

بديل أكثر تجارية إذا أظهرت بيانات Search Console لاحقًا أن نية الأطفال أقوى:

```text
تحفيظ القرآن للأطفال والكبار أونلاين | الحافظ المتميز
```

لا يُطبّق البديل إلا بعد وجود دليل قياس؛ النسخة الأولى أوسع وتشمل البرنامجين.

### الوصف المقترح

```text
تحفيظ القرآن وتعليم التجويد وتأسيس القراءة والكتابة العربية أونلاين بحصص فردية للأطفال والكبار والناطقين بالعربية، مع حصة تجريبية مجانية ومواعيد مرنة.
```

هذا الوصف يذكر:

- تحفيظ القرآن.
- التجويد.
- تأسيس القراءة والكتابة العربية.
- أونلاين.
- حصص فردية.
- الأطفال والكبار.
- الناطقين بالعربية.
- الحصة التجريبية المجانية.

يجب إبقاؤه في حدود مناسبة لعرض نتائج البحث، دون إضافة قائمة دول طويلة.

### المحتوى الأول: H1 المقترح

```text
تحفيظ القرآن وتأسيس اللغة العربية أونلاين للناطقين بالعربية
```

هذا أفضل من جعل H1 عامًا مثل «تعلم القرآن من أي مكان في العالم»، لأن العبارة الأولى تصف الخدمة الفعلية ونية البحث مباشرة.

### الفقرة الأولى تحت H1

```text
حصص فردية مباشرة للأطفال والكبار والمبتدئين، للحفظ والمراجعة وتصحيح التلاوة وتعلم التجويد، ولتأسيس القراءة والكتابة والإملاء باللغة العربية، مع خطة تناسب مستوى الطالب وهدفه.
```

### سطر الثقة أو التوضيح

```text
نتواصل باللغة العربية، وتُعقد الحصص عبر Zoom أو Google Meet، مع مواعيد مرنة للطلاب في الخليج والجاليات العربية حول العالم.
```

يفضل أن يكون هذا نصًا حقيقيًا داخل HTML وليس نصًا داخل صورة.

### أزرار الـCTA

الزر الأساسي:

```text
احجز الحصة التجريبية المجانية
```

الزر الثانوي:

```text
استكشف برامج القرآن والعربية
```

يجب أن يكون الزر الثانوي رابطًا HTML إلى `/quran` أو إلى رابطين واضحين، لا مجرد انتقال داخلي يعتمد على JavaScript.

### ترتيب المحتوى الأول

الترتيب الموصى به في HTML:

1. H1 واحد فقط.
2. فقرة تشرح الخدمة والطلاب المستهدفين.
3. فقرة قصيرة عن اللغة وطريقة الحصة والمواعيد.
4. CTA إلى الحصة المجانية.
5. روابط HTML إلى `/quran` و`/arabic`.
6. قسم «اختر البرنامج المناسب» مع H2.
7. المزايا وطريقة البدء والأسئلة الشائعة.

لا نضع الدول قبل تعريف الخدمة. الدول تُذكر بعد فهم الخدمة أو في روابط مخصصة.

## 4. ما يجب تغييره في `HeroSection`

الملف: `components/home/hero-section.tsx`

التعديلات:

- جعل النص العربي الافتراضي هو الرسالة التجارية المقترحة أعلاه.
- عدم ترك fallback قصيرًا مثل «حصص فردية لتحفيظ القرآن وتأسيس اللغة العربية أونلاين» فقط؛ يجب أن يشمل الناطقين بالعربية والبرنامجين.
- إبقاء `alt` الخاص بصورة الـHero وصفيًا وطبيعيًا، مثل:

```text
أطفال يتعلمون القرآن واللغة العربية أونلاين في حصة فردية
```

- التأكد أن `<h1>` لا يظهر إلا مرة واحدة في HTML الصفحة.
- لا نضيف `meta keywords` كحل رئيسي؛ محركات البحث الحديثة لا تعتمد عليها كعامل ترتيب أساسي. إذا كان فحص لوحة المشروع يتطلب 3–8 كلمات، يمكن الإبقاء على قائمة قصيرة، لكن الأولوية للمحتوى المرئي والعنوان والوصف.
- عدم وضع كل الكلمات في `alt` أو في نص مخفي.

## 5. العلاقة بين Next.js وSupabase وSEO

### المسار الحالي

```text
Next.js App Router
  └─ app/page.tsx
      └─ getPublicContent()
          └─ unstable_cache(revalidate: 3600, tags: ["site-content"])
              └─ siteContentRepository
                  └─ supabaseAdmin
                      └─ public.site_content
```

جدول `site_content` يحتوي على:

- `key`
- `content_ar`
- `content_en`
- `content_fr`
- `section`
- `type`
- `is_active`
- `updated_at`

والقراءة العامة تستخدم المفاتيح النشطة فقط.

### ما هو جيد في التصميم الحالي

- فصل طبقة Repository عن مكوّنات الصفحة.
- استخدام cache لمدة ساعة لتقليل قراءات قاعدة البيانات.
- وجود fallback داخل `localizedContent` إذا كانت قيمة لغة معينة فارغة.
- قصر قراءة الصفحة الرئيسية على مفاتيح محددة بدل قراءة كل CMS.
- وجود RLS وسياسة قراءة للمحتوى النشط.

### ما يحتاج ضبطًا

1. **المحتوى الحرج للـSEO لا يجب أن يختفي عند تعطل CMS.**
   - `hero_title` و`hero_subtitle` يجب أن يكون لهما مصدر ثابت مضمون.
   - قاعدة البيانات تكون مصدر إدارة، لا نقطة فشل تمنع ظهور H1.

2. **فصل cache الـHero عن cache باقي المحتوى.**
   - cache صغير لمفتاحي الـHero.
   - cache منفصل للمحتوى غير الحرج.
   - invalidation واضح بعد حفظ CMS.

3. **توحيد مصدر النص.**
   - حاليًا توجد نصوص داخل `lib/i18n.tsx`، وfallback داخل `HeroSection`، وقيم في `site_content`، ومigrations قديمة.
   - يجب تحديد مصدر أساسي واحد لكل نص، مع fallback ثابت موثق.

4. **مراجعة الـmigrations القديمة.**
   - `022_homepage_copy_refresh.sql` و`023_remove_homepage_hero_copy.sql` تعدلان قيم Hero.
   - هذا طبيعي تاريخيًا، لكن القيمة الحالية الفعلية في Supabase يجب التحقق منها، لا الاعتماد على آخر migration بالاسم.

5. **تجنب القراءة الخادمية بمفتاح غير متاح.**
   - `siteContentRepository` يصبح `null` عندما لا يتوفر `supabaseAdmin`.
   - يجب أن يتعامل المسار مع ذلك قبل `await` أو يستخدم static fallback فورًا.

### سياسة مقترحة للمحتوى

| نوع المحتوى | المصدر الأساسي | fallback | هل يحجب HTML الأولي؟ |
|---|---|---|---|
| H1 وHero subtitle | ثابت خادمي موثوق مع إدارة CMS اختيارية | نص ثابت في الكود | لا |
| SEO title/description | `generateMetadata` في الكود أو إعداد ثابت موثق | قيمة ثابتة | لا |
| قسم البرامج | كود الصفحة | النص الثابت الحالي | لا |
| FAQ الرئيسية | كود الصفحة أو مصدر واحد موحد | FAQ ثابتة | لا |
| فيديوهات الحصص | API/Client بعد IntersectionObserver | عدم عرض القسم | لا |
| بيانات الباقات | Supabase/API | رابط إلى صفحة القرآن | لا |
| المحتوى التسويقي القابل للتحرير | Supabase cache | نص fallback | لا |

## 6. العلاقة بين SEO وقاعدة البيانات في صفحات الدول

صفحات الدول تعتمد على `area_content` وقراءة بيانات المنطقة. بعض الصفحات أعادت في القراءة العامة «جاري تحميل الصفحة»، لذلك يجب فحصها بنفس منهج الصفحة الرئيسية.

لكل صفحة دولة يجب ضمان أن الاستجابة الأولية تحتوي على:

- عنوانًا فريدًا.
- وصفًا فريدًا.
- H1 يذكر الدولة والنية، مثل «تحفيظ القرآن أونلاين للعرب في ألمانيا».
- فقرة فعلية تشرح أن التعليم أونلاين وأن التواصل بالعربية.
- محتوى محلي حقيقي، لا مجرد تغيير اسم الدولة والمدينة.
- سعر وعملة صحيحين إن ظهرا.
- رابطًا يعمل للحجز.
- canonical صحيحًا.
- صورة Open Graph.

لا ينبغي إنشاء صفحات لكل دول العالم قبل التأكد أن:

- البيانات موجودة في `site_areas` و`area_content`.
- الصفحة ترندر HTML قابلًا للقراءة دون انتظار عميل.
- الصفحة تختلف فعليًا في النية والمحتوى.
- الرابط موجود في sitemap فقط إذا كان منشورًا ومكتملًا.

## 7. تحسينات SEO المطلوبة بعد إصلاح الـHero

### أولوية 1: الصفحات التجارية

- `/`
- `/quran`
- `/arabic`
- `/teachers`
- `/faq`
- `/contact`

يجب أن تربط الصفحة الرئيسية بهذه المسارات بروابط HTML واضحة، مع نص رابط وصفي مثل:

- تفاصيل برنامج تحفيظ القرآن والتجويد.
- تفاصيل تأسيس اللغة العربية أونلاين.
- تعرّف على المعلمين والمعلمات.
- الأسئلة الشائعة عن الحصص الفردية.

### أولوية 2: أسواق محددة

ابدأ بالصفحات التي تجمع بين حجم سوق منطقي ووجود محتوى عربي مخصص:

- السعودية.
- الإمارات.
- الكويت.
- قطر.
- عُمان والبحرين.
- الولايات المتحدة.
- بريطانيا.
- كندا.
- أستراليا.
- ألمانيا وفرنسا.

بعد ذلك تُراجع بقية الدول. الهدف ليس استهداف العالم كله بنفس الكلمات، بل بناء مجموعات نية واضحة.

### أولوية 3: المدونة

كل مقال يجب أن يرتبط بصفحة خدمة ذات صلة. أمثلة:

- مقال عن تقنيات حفظ القرآن يربط إلى `/quran`.
- مقال عن تأسيس العربية للأطفال يربط إلى `/arabic`.
- مقال عن تعليم القرآن للعرب في دولة معينة يربط إلى صفحة الدولة ذات الصلة.

لا ننشئ مقالات كثيرة مولدة آليًا لمجرد زيادة عدد الصفحات.

### البيانات المنظمة

الموقع يحتوي بالفعل على Schema، لذلك لا نضيف نسخًا مكررة عشوائيًا. نراجع فقط:

- `EducationalOrganization`.
- `WebSite`.
- `WebPage`.
- `FAQPage` عندما يطابق الأسئلة الظاهرة.
- `BlogPosting` للمقالات.
- `Person` للمعلمين.

يجب ألا نضيف `LocalBusiness` أو فروعًا محلية لأن الخدمة أونلاين ولا توجد فروع مثبتة.

## 8. خطة تنفيذ على مراحل

### المرحلة الأولى: إصلاح الرندر الأساسي

1. إزالة اعتماد الـHero على مجموعة CMS كاملة.
2. إخراج H1 والوصف والـCTA من `Suspense` الحاجب.
3. استبدال fallback العام بواجهة محايدة غير نصية.
4. توحيد نص Hero العربي بين `app/page.tsx` و`HeroSection` و`site_content`.
5. التأكد من عدم وجود H1 ثانٍ.

### المرحلة الثانية: تحسين Metadata والمحتوى

1. تثبيت title واحد للصفحة الرئيسية.
2. تحديث meta description بالمقترح.
3. تحديث H1 والفقرة الأولى.
4. تقوية روابط `/quran` و`/arabic`.
5. إبقاء CTA واضحًا ومباشرًا.

### المرحلة الثالثة: فصل بيانات CMS

1. تعريف قائمة `criticalSeoContent`.
2. تعريف قائمة `enhancementContent`.
3. منع فشل `enhancementContent` من حجب الصفحة.
4. إضافة cache/invalidation واضحين.
5. تسجيل فشل CMS دون تسريب بيانات أو إظهار شاشة تحميل للمستخدم.

### المرحلة الرابعة: صفحات الدول

1. اختبار HTML الأولي لصفحات السعودية وألمانيا والولايات المتحدة وأستراليا.
2. مقارنة `title`, `description`, `h1`, canonical وOG.
3. إصلاح الصفحات التي تعيد «جاري تحميل الصفحة» أو HTML فارغًا.
4. مراجعة وجود كل صفحة في `sitemap.xml` فقط عند اكتمالها.
5. تقليل الأولوية للدول التي لا تملك محتوى عربيًا مختلفًا فعليًا.

### المرحلة الخامسة: القياس

بعد النشر، نقيس دون الاعتماد على Semrush المدفوع:

- Search Console: مرات الظهور والنقرات وCTR والموضع.
- فحص HTML الخام باستخدام curl أو أداة بدون JavaScript.
- عنوان الصفحة والوصف وH1 في كل route.
- حالة HTTP للصفحات الموجودة والمفقودة.
- Lighthouse للهاتف.
- نقرات WhatsApp كتحويل.

## 9. معايير القبول بعد التنفيذ

تُعتبر المرحلة الأولى ناجحة عندما تتحقق الشروط التالية:

- طلب `GET /` يعيد H1 العربي داخل HTML الأولي دون تشغيل JavaScript.
- لا تظهر عبارة «جاري تحميل الصفحة» بدل محتوى الصفحة الرئيسية في الاستجابة النهائية.
- H1 موجود مرة واحدة فقط.
- title بين 30 و60 حرفًا تقريبًا.
- meta description بين 50 و160 حرفًا تقريبًا.
- HTML الأولي يحتوي على فقرة الخدمة وروابط `/quran` و`/arabic`.
- تعطل Supabase أو غياب `SUPABASE_SERVICE_ROLE_KEY` لا يمنع ظهور Hero.
- `sitemap.xml` و`robots.txt` يعملان ويشيران إلى الدومين canonical.
- صفحات الدول المختبرة لا تعيد shell فارغًا أو صفحة نجاح بلا محتوى.
- النص الظاهر وFAQ وSchema متطابقة، ولا يوجد Schema لمحتوى غير ظاهر.

أوامر تحقق مقترحة:

```bash
curl -L -s https://quran-elhafez.com/ | rg -n "<h1|تحفيظ القرآن|اللغة العربية|جاري تحميل"
curl -L -s https://quran-elhafez.com/quran | rg -n "<h1|تحفيظ القرآن|التجويد|جاري تحميل"
curl -I https://quran-elhafez.com/
curl -L -s https://quran-elhafez.com/sitemap.xml
curl -L -s https://quran-elhafez.com/robots.txt
```

يجب تكرار الفحص باستخدام User-Agent عادي وUser-Agent لمحرك بحث، لأن نجاح المتصفح وحده لا يثبت أن HTML الأولي قابل للفهرسة.

## الملفات المتوقع تعديلها عند اعتماد التنفيذ

- `app/page.tsx`: إخراج الـHero من انتظار CMS أو فصل القراءة الحرجة عن غير الحرجة.
- `components/home/hero-section.tsx`: تحديث fallback والنص العربي والروابط إن لزم.
- `app/layout.tsx` أو Metadata الصفحة الرئيسية: توحيد title والوصف ومنع التكرار.
- `app/loading.tsx`: إزالة نص التحميل من fallback العام واستبداله بـskeleton محايد.
- `lib/public-content-server.ts`: إضافة مسار آمن للمحتوى الحرج إذا تقرر إبقاء CMS.
- `lib/repositories/supabase/site-content-repository.ts`: لا يحتاج تغييرًا وظيفيًا غالبًا، إلا إذا أضيف timeout أو استعلام مخصص للـHero.
- `supabase/migrations/*`: لا تُنشأ migration جديدة لتعديل النص إلا إذا كان مصدر CMS سيبقى معتمدًا؛ وإلا يكفي توحيد fallback والكود ثم تحديث القيمة من لوحة الإدارة.
- `app/sitemap.ts` و`app/robots.ts`: مراجعة فقط بعد إصلاح الرندر، وليس تغييرهما كبديل عن إصلاح HTML.

## القرار التقني المقترح

أفضل توازن للموقع هو:

1. H1 وHero subtitle وmetadata ثابتة ومضمونة في Next.js.
2. Supabase يدير النصوص القابلة للتحرير بعد وجود fallback ثابت.
3. لا توجد قراءة قاعدة بيانات تحجب المحتوى الأول.
4. المحتوى الاختياري مثل الفيديوهات والباقات يظل مؤجلًا أو Client-side.
5. صفحات الدول تستخدم قاعدة البيانات فقط عندما تملك محتوى مكتملًا وفريدًا، مع fallback واضح وعدم نشر صفحات فارغة.

هذا يحل مشكلة القراءة لمحركات البحث، ويقلل أثر تعطل قاعدة البيانات، ويحافظ في الوقت نفسه على لوحة التحكم وإدارة المحتوى.
