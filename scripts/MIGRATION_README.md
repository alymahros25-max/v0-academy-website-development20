# ترحيل Preview المركزي

الملف `migrate-central-preview.ts` يجهّز ترحيلًا واحدًا قابلًا لإعادة التشغيل من مصادر الفرع إلى قاعدة Supabase الجديدة المرتبطة بـ Vercel Preview.

## ما يرحّله

- جميع صفحات الدول الأربعين من إعدادات الصفحات الحالية.
- ثمانية باقات لكل دولة: أربعة للقرآن وأربعة للعربية.
- المحتوى الأساسي لكل دولة، والأسئلة الشائعة، والروابط، والثيم، والمدن، والمنطقة الزمنية.
- الباقات العامة من `data/packages.json`.
- المعلمون من `data/teachers.json`.
- التقييمات من `data/reviews.json`.
- الرسائل من `data/messages.json`.
- إعدادات الموقع العامة من `data/settings.json` إلى `admin_content` و`site_settings` و`site_content`.
- الألعاب ليست ضمن ترحيل قاعدة البيانات: مصدرها هو الكود العادي في `lib/games-data.ts` ومكونات `components/games`، وصفحة `/games` تستدعيها مباشرة. هذا يمنع إنشاء نسخة ثانية قد تتعارض مع الألعاب العاملة.

## ما لا ينقله عمدًا

لا توجد في الفرع نسخة مصدر معتمدة مستقلة للمجالات التالية، لذلك لا يخترع السكربت بيانات لها ولا يقرأها من قاعدة Production القديمة:

- مقالات المدونة.
- الفيديوهات.
- المكتبة الرقمية.
- الصفحات القانونية.
- إعدادات الودجات.
- صفحات `site_pages` المنشأة من محرر الصفحات.
- الأسئلة العامة إن لم يوجد لها ملف مصدر مستقل.

يجب تزويد هذه المجالات بملفات محتوى معتمدة قبل إضافتها إلى نفس الترحيل؛ تركها فارغة أفضل من نقل نسخة قديمة غير معتمدة أو بيانات اختبارية.

## محتوى CMS المعتمد في Preview

الملف `seed-preview-content.ts` يضيف إلى قاعدة Preview فقط:

- مقالتين منشورتين عن حفظ القرآن وتأسيس العربية، بروابط نظيفة.
- ثلاثة أسئلة عامة باللغات الثلاث.
- الصفحات القانونية الثلاث باللغات العربية والإنجليزية والفرنسية.
- إعداد زر WhatsApp وشريط التنقل.
- صفحتي `about` و`faq` في محرر الصفحات.

تشغيل جاف:

```bash
./node_modules/.bin/tsx scripts/seed-preview-content.ts
```

أما الفيديوهات وملفات Google Drive فلا تُنشأ بروابط وهمية؛ عند توفير الروابط الفعلية يمكن تسجيلها من لوحة التحكم، والتحقق من حفظها وعرضها.

## التشغيل

وضع المعاينة الجافة هو الافتراضي ولا يكتب شيئًا:

```bash
./node_modules/.bin/tsx scripts/migrate-central-preview.ts
```

أو بعد تثبيت الاعتماديات:

```bash
pnpm migration:preview
```

التطبيق الفعلي يحتاج متغيري الحماية مع مفاتيح Vercel Preview فقط:

```bash
VERCEL_ENV=preview MIGRATION_TARGET=preview \
  NEXT_PUBLIC_SUPABASE_URL='قيمة Preview' \
  SUPABASE_SERVICE_ROLE_KEY='مفتاح Preview' \
  ./node_modules/.bin/tsx scripts/migrate-central-preview.ts --apply
```

لا تشغّل `--apply` من Production. السكربت يرفض التنفيذ إذا لم تكن `VERCEL_ENV=preview` و`MIGRATION_TARGET=preview`، ولا يقرأ قاعدة البيانات القديمة.

## المتطلبات

طبّق ملفات المخطط الثلاثة بالترتيب على قاعدة Preview الفارغة قبل التطبيق:

1. `db/isolated/0001_clean_baseline.sql`
2. `db/isolated/0002_admin_content.sql`
3. `db/isolated/0003_admin_editors.sql`

السكربت يستخدم upsert للمحتوى المملوك للمصدر، ولا يحذف سجلات غير معروفة. لا يتم الدمج أو تغيير متغيرات Production ضمن هذه العملية.
